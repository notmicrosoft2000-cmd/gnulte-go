About GNULTE

Seven Linux tools for testing how devices behave on a degraded network.

01 /

What it is

GNULTE, the GNU LAN Network Testing Environment, shapes a bad link with the kernel's tc queues and watches how a device responds. It restores the link afterwards.

The suite covers discovery (gnulte-scan, gnulte-inventory), live observation (gnulte-watch, gnulte-watch top), impairment (gnulte), path analysis (gnulte-watch trace), Wi-Fi disassociation testing (gnulte-wifi) and pre-flight verification (gnulte-quicksum). The tools share one device store. A watch supplies the target list; a scan supplies the baseline.

02 /

Development philosophy

No third-party dependencies
The toolkit is Go standard library against the Linux kernel. Since the Unplugged programme it needs no arping, arp-scan, tcpdump, ping or traceroute(8). tc and iptables remain. They are the kernel interface.
Plain verification
Every fix ships with a discriminating regression test. go vet and go test ./... must pass before a version bump; GOOS=darwin go vet keeps portable code from rotting.
Small, shippable increments
The changelog is a list of steps, each independently useful, each dated and committed.
Cleanup is part of the feature
Every run restores the previous qdisc and ip_forward. A second Ctrl+C is needed to force an exit mid-teardown, so a target is never left with a poisoned ARP cache.
Documentation-first
Every tool has a -h that explains itself, a machine-readable output mode (--json at minimum) and a report you can file after the run.
03 /

Authorised use

GNULTE performs ARP-based man-in-the-middle routing, kernel-level traffic impairment, packet capture, LAN discovery and 802.11 injection. Only use these tools on networks, systems and devices you own or are explicitly authorised to test. The authors grant no permission to test any particular third-party network; users are responsible for complying with applicable laws, contracts and policies.

This is enforced in code where possible: gnulte-quicksum reports the safety record, the engine refuses to target the gateway or your own machine, and tools that need consent require an explicit acceptance record (--reset-safety clears it). The safety documents are printed by gnulte --docs and gnulte-scan --docs.

Source and contributions

Development happens in the open at github.com/notmicrosoft2000-cmd/gnulte-go. There is no mailing list or forum; the issue tracker is the point of contact for bugs and patches.

Bug reports
Include the output of gnulte-quicksum --json and the exact command line. That is most of a diagnosis.
Patches
Pull requests against main. Standard library only, no gofmt drift, tests required.
Plan
The upstream plan for upcoming releases is docs/V17-PLAN.md.
Credits
Maintained by Neptune Productions. Built on tc/netem, netfilter, AF_PACKET and mac80211, and on prior art from arpwatch and iperf to mtr and nethogs.
