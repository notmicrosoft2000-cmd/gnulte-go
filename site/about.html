About GNULTE

Last updated 2026-10-15

What GNULTE is

GNULTE — the GNU LAN Network Testing Environment — is a suite of eight Linux tools for measuring how devices behave when their network misbehaves. It does one narrow job well: it lets an authorised operator put a real, kernel-shaped bad network in front of a real device and watch what the device does about it — then clean up completely afterwards.

The suite covers discovery (gnulte-scan, gnulte-devices), live observation (gnulte-lan, gnulte-top), impairment (gnulte), path analysis (gnulte-trace), Wi-Fi disassociation testing (gnulte-wifi) and pre-flight verification (gnulte-doctor). The tools share one device store, so a watch becomes a target list and a scan becomes a baseline.

Development philosophy

  • Zero third-party dependencies. The whole toolkit is Go standard library against the Linux kernel. Since the v17 Unplugged programme it runs on a bare box: no arping, arp-scan, tcpdump, ping or traceroute(8). tc and iptables remain — they are the kernel interface, not wrappers.
  • Verification is plain go test. Every fix ships with a discriminating regression test; go vet and go test ./... must pass before a version bump. GOOS=darwin go vet stays clean so the portable code never rots.
  • Small, shippable increments. The changelog is a list of steps, each one independently useful, each one dated and committed.
  • Cleanup is part of the feature. Every run restores the previous qdisc and the previous ip_forward value; a second Ctrl+C is needed to force an exit mid-teardown.
  • Documentation-first. Every tool has a -h that explains itself, a machine-readable output mode (--json at minimum) and a report you can file after the engagement.

Authorised use

GNULTE performs ARP-based man-in-the-middle routing, kernel-level traffic impairment, packet capture, LAN discovery and 802.11 injection.

Only use these tools on networks, systems and devices you own or are explicitly authorised to test. The authors grant no permission to test any particular third-party network; users are responsible for complying with all applicable laws, contracts and policies.

The toolkit takes this seriously in code: gnulte-doctor reports the state of the safety record, the engine refuses to target the gateway or your own machine, and every tool that needs consent requires an explicit acceptance record (clear it with --reset-safety). The safety documents are printed by gnulte --docs and gnulte-scan --docs.

Source and contributions

Development happens in the open at github.com/notmicrosoft2000-cmd/gnulte-go.

Bug reports
Open an issue on the issue tracker. Include the output of gnulte-doctor --json and the exact command line — that is most of a diagnosis.
Patches
Pull requests are accepted against main. New code must be standard library only, must not add gofmt drift, and must ship with tests. The upstream plan for upcoming releases is docs/V17-PLAN.md.
Contact
There is no mailing list or forum; the issue tracker is the point of contact for both bugs and patches.

Credits

GNULTE is maintained by Neptune Productions. It stands on the shoulders of the Linux networking stack — tc/netem, netfilter, AF_PACKET sockets and mac80211 — and on two decades of prior art in LAN measurement tools, from arpwatch and iperf to mtr and nethogs.
