CONTACT & REPORTING

Where to write

Bug reports, patches and security reports all go through the public repository.

01 /

Bugs and patches

Open an issue on the issue tracker. Include the exact command line, the output of gnulte-doctor --json, the kernel version and what you expected to happen. That is most of a diagnosis.

Patches are pull requests against main: standard library only, no gofmt drift, tests included. The roadmap lives in docs/V17-PLAN.md.

Open an issueContribution notes
02 /

Security reports

Use GitHub’s private vulnerability reporting on the repository for issues in raw-socket handling, privilege boundaries or buffer integrity. Do not open a public issue for an undisclosed vulnerability.

No signed binary releasesCompare the commit hash against the tag and read the source. No binary signatures are published.

GNULTE

GNU LAN Network Testing Environment. Eight single-purpose Linux tools, standard library only, GPL-3.0-or-later.

Maintained by Neptune Productions. Built on tc/netem, netfilter, AF_PACKET and mac80211.
