Frequently asked questions

Applies to GNULTE v16.13 · last updated 2026-10-15

Which platforms are supported?
Linux. The code is written so the portable parts compile elsewhere (platform-specific files sit behind *_linux.go build tags and GOOS=darwin go vet must stay clean), but everything that matters — raw sockets, AF_PACKET capture, tc netem, monitor-mode injection — is Linux. There is no Windows or macOS support and none is planned for v17.
Which tools need root?
gnulte (shaping and spoofing), gnulte-wifi (injection), gnulte-trace and gnulte-top (raw sockets). gnulte-lan and gnulte-scan run unprivileged with reduced coverage (no flows screen, no per-host rates), gnulte-devices and gnulte-doctor need no privileges at all.
Do I need arp-scan, arping, tcpdump, ping or traceroute?
No. Since v16.6–v16.10 (the Unplugged programme) ARP sweeping, ICMP echo, packet capture and path probing are implemented in-process. The only external programs the toolkit invokes are tc and iptables, which are the kernel interface, not wrappers around anything.
Why does it need tc and iptables at all?
Because that is how the Linux kernel configures traffic shaping and forwarding. A program cannot netem a qdisc without them, and reimplementing netlink for two ioctls would be a dependency in disguise.
Where does GNULTE store its data?
State under ~/.config/gnulte-go/ (settings, the shared device store, the acceptance record, profiles, the watch timeline) and reports under ~/GNULTE Reports/. Nothing is written outside your home directory except the binaries in /usr/local/bin.
What is the “safety record”?
An explicit authorised-use acceptance record stored in ~/.config/gnulte-go/acceptance.json. Consent-gated tools ask once and remember; --reset-safety on any tool clears it. The state of the record is part of gnulte-doctor's report.
Will it shape my own machine or the gateway?
No. The engine refuses to target the gateway or the machine it runs on, and every parameter is validated before the run starts with its impact estimated out loud.
Is there a GUI?
No. The tools are terminal applications; the interactive ones are full-screen console UIs. Reports are self-contained HTML files you can open in any browser.
Can I script it?
Yes. Every tool supports --json at minimum; most also support --csv or --yaml, --quiet and an explicit --duration. gnulte-doctor exits non-zero on failure so a script can gate on it.
How do I report a bug?
Open an issue on the issue tracker with gnulte-doctor --json output, the exact command line, your distribution and kernel version.
What licence is it?
GPL-3.0-or-later. The full text ships in the repository as LICENSE.
May I use it on a network at work or school?
Only if you own it or are explicitly authorised to test it. Authorisation from your own desk is not authorisation. See authorised use.
