gnulte-wifi(8) — Wi-Fi disassociation testing

Applies to gnulte-wifi v16.13 · last updated 2026-10-15

An 802.11 Deauthentication frame is crafted with the source MAC set to the access point's BSSID and the destination set to one station. The station assumes its router disconnected it and drops the Wi-Fi association — the same behaviour as a router's “kick client” control, reproduced for authorised testing.

Authorised testing only. Deauthenticating clients on a network you do not own or are not explicitly authorised to test is illegal in most jurisdictions. GNULTE requires an explicit acceptance record before it will run.

Requirements

  • Root.
  • A wireless interface already in monitor mode (airmon-ng start wlan0 or iw dev wlan0 set type monitor). GNULTE does not change the interface mode itself.
  • An adapter that supports injection; some cap injection rates (raise --count if a single frame rarely lands).

Synopsis

sudo gnulte-wifi -i IFACE -a APBSSID -s STATIONMAC

sudo gnulte-wifi -i wlan0mon -a 00:0c:41:63:45:6a -s aa:bb:cc:dd:ee:ff

Options

OptionDescription
-i, --interface IFACEwireless interface in monitor mode (e.g. wlan0mon)
-a, --ap MACaccess point BSSID (the router's MAC)
-s, --station MACstation to disconnect; ff:ff:ff:ff:ff:ff = every client on the BSSID
--reason CODE802.11 deauth reason code (default 7 = STA leaving BSS)
--count Nframes per burst (default 64)
--delay SECONDSseconds between bursts (repeat kicks a client that reconnects; default 5)
--jitter-ms Nrandom 0–N ms delay before each frame — irregular timing defeats reconnect timers (0 = no jitter)
--mixrotate the reason code each burst (default on; off when --reason is given explicitly)
--hop-channelshop the adapter through a channel list after each burst, so a channel-hopping AP stays in range
--channels LISThop list, comma-separated (default 1,6,11)
--oncesend a single burst and exit
--duration SECONDSauto-stop after N seconds (0 = until Ctrl+C)
--forceskip interactive confirmations
--no-bannerskip the banner (alias: --minimal)
-q, --quietresults only
--settingsopen the settings editor and exit
--docsprint the safety documents and exit
--reset-safetyremove the acceptance record and exit
--versionprint version and exit
-h, --helpshow the built-in help

Examples

sudo gnulte-wifi -i wlan0mon -a 00:0c:41:63:45:6a -s aa:bb:cc:dd:ee:ff --once
sudo gnulte-wifi -i wlan0mon -a 00:0c:41:63:45:6a -s ff:ff:ff:ff:ff:ff --duration 60 --jitter-ms 150

Installation

Part of the GNULTE suite. Build and install everything at once;

git clone https://github.com/notmicrosoft2000-cmd/gnulte-go.git
cd gnulte-go
./build.sh          # builds all eight binaries, runs go vet + go test ./...
sudo ./install.sh   # installs to /usr/local/bin + safety docs

installs gnulte-wifi to /usr/local/bin/gnulte-wifi. See installation for requirements.

Common errors

Nothing is injected
Check the interface is in monitor mode (airmon-ng start / iw dev ... set type monitor); GNULTE does not switch the mode itself.
The station rarely drops
Some adapters cap injection rates: raise --count, add --jitter-ms, and repeat with --delay.
The client will not stay disconnected
That is expected for a single burst — a station that rejoins is kicked again on the next burst, which is what --delay repeats.
