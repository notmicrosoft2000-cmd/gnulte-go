GNU LAN NETWORK TESTING ENVIRONMENT · v17.0

GNULTE

Eight Linux executables for observing, testing and impairing a network you own or are explicitly authorised to test. They work at the kernel's queue layer, in the foreground, with no background service and no account.

Capabilities

  • 01

    Network inspection

    Neighbour tables, ARP frames, vendors, hostnames and device types.

    gnulte-inventory, gnulte-scan

    ip neigh · ARP · mDNS
  • 02

    Traffic impairment

    Latency, jitter, loss, duplication, reordering and bandwidth caps on one target.

    gnulte

    tc netem · delay / loss
  • 03

    Live observation

    Hosts, top talkers, per-pair conversations, alarms and up/down history.

    gnulte-watch

    seven screens · passive
  • 04

    Path and throughput

    Per-hop loss and latency, then per-host and per-flow bandwidth from raw frames.

    gnulte-watch trace, top

    ICMP TTL · AF_PACKET
  • 05

    Port and service discovery

    Parallel sweep, in-Go TCP scan, banners, OUI vendors and OS guesses.

    gnulte-scan

    TCP · banners · OUI
  • 06

    Wi-Fi testing

    Targeted 802.11 disassociation for authorised client-reconnect tests.

    gnulte-wifi

    monitor mode · root
  • 07

    Reports

    List, merge, diff and file the JSON and HTML output from a test run.

    gnulte-report

    merge · diff · archive

Technical philosophy

The design constraints are part of the tool, not a marketing layer.

Native Linux integration

Shaping uses tc netem and netfilter; observation uses AF_PACKET, raw ICMP and mac80211. tc and iptables remain because they are the kernel interface.

Inspectable by design

Every command has -h, machine-readable output where it makes sense, and a report you can read after the run. The source is the release artifact.

No background services

Tools run in the foreground. A shaping run restores the previous qdisc and ip_forward on exit; a second Ctrl+C is needed only to force an interrupted teardown.

Local-first state

Configuration, device store, acceptance record and reports live under the user's home directory. There is no account, cloud component or telemetry channel.

User-controlled targeting

The engine refuses to target the gateway or the operator's own machine. Consent is recorded locally and can be reset explicitly.

Honest boundaries

GNULTE shows host context such as resolver status and listening sockets. It does not decide whether a DNS policy or firewall rule is correct; that judgement stays with the operator.

Install from source

Go 1.21 or newer. No third-party Go modules. Distro package prerequisites are on the download page.

terminal
git clone https://github.com/notmicrosoft2000-cmd/gnulte-go.git
cd gnulte-go
./build.sh
sudo ./install.sh
gnulte-hub

build.sh runs go vet ./cmd/... ./internal/... and go test ./cmd/... ./internal/... before it hands over binaries. install.sh reads the version from the built tools and aborts if they disagree.

Before you run it

Authorised use onlyGNULTE redirects ARP traffic, impairs kernel queues, captures packets and can inject 802.11 management frames. Use it only on networks, systems and devices you own or are explicitly authorised to test. Read the policy or run gnulte --docs.
