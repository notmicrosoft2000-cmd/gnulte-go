GNULTE/Architecture
SUITE ARCHITECTURE · v17.0

Workstation architecture

Eight executables sharing one device store. GNULTE does not sit inline as a proxy; it reads kernel state and changes kernel queues for the duration of a run.

01 /

Control flow

operator

The operator starts from a shell or the plain-language menu. Every tool runs in the foreground; nothing is installed as a daemon.

$ gnulte-hub

Illustrative control flow. The device store is ~/.config/gnulte-go/devices.json.

03 /

Boundaries

What it is

A set of foreground Linux utilities built on the kernel's own network interfaces. State stays in the user's home directory; output is inspectable as text, JSON, CSV or HTML.

What it is not

Not a resolver-policy auditor, firewall manager, SIEM or always-on agent. Resolver status, listening sockets and firewall state may be shown as host context, but GNULTE does not rule on their correctness.

Dependency noteGo code is standard-library only. tc and iptables remain because they are the interface to the kernel, not helper binaries the toolkit could replace.
