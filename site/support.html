HELP

Getting help

Most problems are privileges or kernel modules. Run the doctor first, then read the troubleshooting matrix. If neither answers it, open an issue with the exact command and the doctor’s JSON output.

01 /

Step 1: run the doctor

gnulte-doctor checks privileges, binaries, forwarding, modules, route, duplicates and the safety record. It prints PASS/WARN/FAIL with fix hints, supports --json, and exits non-zero when a check fails, so a script can gate on it.

pre-flight
gnulte-doctor --json

Common problems

SymptomCauseFix
Operation not permitted / raw socket errorNo capability for AF_PACKET or IPPROTO_ICMP socketsRun with sudo, or grant cap_net_raw,cap_net_admin.
RTNETLINK answers: No such file or directorysch_netem not loadedsudo modprobe sch_netem; install kernel modules.
Target loses connectivity after a runForwarding disabled or a run killed with kill -9Check ip_forward; end runs with Ctrl+C. Restart the interface if the ARP entry is poisoned.
iptables: No chain/target/match by that nameMissing netfilter modules or legacy/nftables conflictsudo modprobe iptable_mangle and iptable_nat.
Wi-Fi injection failsInterface not in monitor mode or wrong regulatory domainiw dev wlan0 set type monitor; verify chipset support.

Where to ask

No private support channel. This is a free-software project; the issue tracker is the point of contact.

GNULTE

GNU LAN Network Testing Environment. Eight single-purpose Linux tools, standard library only, GPL-3.0-or-later.

Maintained by Neptune Productions. Built on tc/netem, netfilter, AF_PACKET and mac80211.
