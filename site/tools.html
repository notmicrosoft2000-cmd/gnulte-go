Tool directory

Applies to GNULTE v16.13 · last updated 2026-10-15

GNULTE ships eight binaries. Each does one job; the tools interconnect through a shared device store (~/.config/gnulte-go/devices.json) that every tool reads and writes. Root says whether the tool needs privileges to do its work: without them it either degrades gracefully (marked optional) or cannot run at all (marked yes).

BinaryRootPurposeStatusReference
gnulte yes Traffic shaping engine: latency, jitter, loss, duplication, reordering and bandwidth caps via tc netem, routed through your machine with ARP spoofing. Live dashboard, tc -s qdisc telemetry, HTML report. stable gnulte(8)
gnulte-lan optional Live LAN watch: six screens — hosts, talkers, flows, ARP neighbours, a live interconnection map and session history. Passive: frames are counted, nothing is shaped or intercepted. stable gnulte-lan(8)
gnulte-scan optional Sweep plus deep scan: parallel ICMP/ARP sweep, in-Go TCP port scanner, OUI vendor lookup, mDNS/NetBIOS names, OS fingerprinting, live re-scanning with --watch N and a -T tabbed browser. stable gnulte-scan(8)
gnulte-devices no Instant device inventory from the kernel ARP/neighbour table — vendors, mDNS hostnames, type guesses; CSV/JSON/YAML or an HTML report. stable gnulte-devices(8)
gnulte-wifi yes Targeted 802.11 deauthentication from monitor mode — the same behaviour as a router's “kick client” control, for authorised disassociation testing. Per-frame jitter, rotating reason codes, channel hopping. stable gnulte-wifi(8)
gnulte-doctor no Pre-flight health check: privileges, tc/iptables, ip_forward, netem/netfilter modules, default route, duplicate IPs and the safety record. PASS/WARN/FAIL with fix hints; scriptable via --json and its exit code. stable gnulte-doctor(8)
gnulte-trace yes mtr-style path probe: in-process ICMP echo at every TTL with per-hop last/avg/best/worst and loss. No traceroute(8) required. stable gnulte-trace(8)
gnulte-top yes Live bandwidth view: per-host and per-conversation rates from an in-process AF_PACKET counter, ranked with ↓/↑ rates, peer counts and bars. stable gnulte-top(8)

How the tools fit together

A typical engagement moves through the suite in one direction:

  1. gnulte-scan --deep or gnulte-devices -s discovers what is on the LAN.
  2. gnulte-lan watches it live and, with x, folds the inventory into the shared device store.
  3. gnulte -t <ip> shapes one host (press ⏎ in the watch to hand off directly), or a whole range.
  4. gnulte-top and gnulte-trace measure the effect; gnulte-doctor proves the machine was ready before you started.

See usage for worked recipes and documentation for the full manual.
